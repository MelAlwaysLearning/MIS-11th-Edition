Chapter 13 · SDLC
The Systems Development Life Cycle (SDLC)
The traditional "waterfall" method: finish each stage before starting the next. Click each stage.
🔎
1. Planning & Analysis
Investigate the problem, check feasibility (technical, economic, organizational), and gather detailed requirements.
Click to reveal
✏️
2. Design
Specify how the system will work: screens, databases, networks, security and processes. Output: a detailed blueprint.
Click to reveal
💻
3. Build & Test
Programmers write code (or configure software), then test in layers — unit, system and user acceptance testing.
Click to reveal
🚀
4. Implement & Maintain
Deploy, train users and support the system. Maintenance is the longest, costliest phase — fixes and enhancements for years.
Click to reveal
Exam Trap Analysis asks what the system must do; design asks how it will do it. Know the order: Plan → Analyze → Design → Build/Test → Implement → Maintain.

Chapter 13 · Comparison
Waterfall vs. Agile
A very common exam comparison.
FeatureWaterfall (SDLC)Agile
Structure Sequential phases, each finished before the next Short iterative cycles (sprints)
Requirements Fixed up front Expected to change; adapt each sprint
User involvement Mainly at start and end Continuous throughout
Delivery One big release at the end Working increments every few weeks
Best for Stable, well-understood, regulated projects Uncertain or fast-changing needs
Risk Problems found late Scope drift if not managed
Key Point Neither is "best." Choose by how stable the requirements are and how much risk of late surprises you can afford.

Chapter 13 · Takeaways
What You Must Know
  • Systems development = creating or acquiring an IS. Most failures come from poor requirements, scope creep and weak management — not technology.
  • SDLC stages: Planning/Analysis → Design → Build/Test → Implement → Maintain. Analysis = what; design = how. Maintenance is the longest and costliest phase.
  • Agile builds in short sprints with constant user feedback; waterfall is sequential with fixed requirements. Prototyping and RAD speed up unclear projects.
  • Acquire by buying off-the-shelf, building custom, renting SaaS or outsourcing. Build only for competitive advantage.
  • Feasibility: technical, economic and organizational. Triple constraint: scope, time, cost. Change management drives adoption.
  • Conversion strategies: direct (riskiest), parallel (safest, costliest), phased, pilot.
